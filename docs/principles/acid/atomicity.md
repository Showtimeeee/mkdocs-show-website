# Atomicity (Атомарность)

**Atomicity (Атомарность)** — свойство транзакции, которое гарантирует, что она выполняется как **единое неделимое целое**. Либо транзакция выполняется полностью и успешно, либо не выполняется вообще (откатывается к исходному состоянию).

#### **Основная концепция**

- Транзакция — это набор операций, которые должны быть выполнены **все вместе**.
- Если хотя бы одна операция завершилась ошибкой — **все изменения откатываются**.
- Не может быть ситуации, когда часть изменений применилась, а часть нет.
- **"Всё или ничего"** — нет промежуточных состояний.

#### **Ключевые механизмы**

1. **BEGIN** — начало транзакции.
2. **COMMIT** — фиксация всех изменений.
3. **ROLLBACK** — откат всех изменений при ошибке.
4. **Журнал транзакций (Write-Ahead Log)** — для восстановления после сбоев.

#### **Преимущества**

1. Целостность данных
2. Восстановление после сбоев
3. Упрощение разработки (группировка операций)

---

### Пример: Банковский перевод

**Без атомарности** — деньги списались, но не зачислились:

```python
# ❌ Деньги потеряны!
src.balance -= 1000  # Списано
# Ошибка! База упала
dst.balance += 1000  # Не выполнилось
```

**С атомарностью** — всё или ничего:

```sql
BEGIN TRANSACTION;

UPDATE accounts SET balance = balance - 1000 WHERE id = 1;  -- Списываем
UPDATE accounts SET balance = balance + 1000 WHERE id = 2;  -- Зачисляем

COMMIT;  -- ✅ Если всё ок
-- ROLLBACK;  -- ❌ Если ошибка — всё откатится
```

В коде:

```python
try:
    db.begin()
    src.withdraw(1000)
    dst.deposit(1000)
    db.commit()  # ✅ Фиксируем
except Exception:
    db.rollback()  # 🔄 Откатываем
    raise
```

---

### Когда использовать

| Ситуация | Нужна ли атомарность |
|----------|---------------------|
| **Банковские переводы** | ✅ Обязательно |
| **Оформление заказа** (списание товара + денег) | ✅ Обязательно |
| **Регистрация пользователя** (создать профиль + отправить email) | ✅ Да |
| **Чтение данных** (SELECT) | ❌ Нет |
| **Логирование** | ❌ Нет |

---

### Лучшие практики

1. **Короткие транзакции** — чем короче, тем меньше блокировок и конфликтов.
2. **Все проверки до BEGIN** — валидацию делайте до начала транзакции.
3. **Всегда обрабатывайте исключения** — при любой ошибке должен быть ROLLBACK.
4. **Авто-коммит выключить** — чтобы каждая операция не фиксировалась автоматически.

---

### Пример из жизни: Покупка в интернет-магазине

**Без атомарности:**
- Деньги списались, но товара нет → вы без денег и без товара ❌

**С атомарностью:**
- Если ошибка — деньги возвращаются, товар освобождается ✅

---

### Вывод

**Атомарность** — это **"всё или ничего"**. Либо транзакция выполняется полностью, либо полностью откатывается. Без атомарности сбои приводят к повреждению данных. Используйте транзакции для всех операций, которые изменяют несколько сущностей.
