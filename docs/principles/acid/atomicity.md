# Принцип ACID: Atomicity (Атомарность)

**Atomicity (Атомарность)** — свойство транзакции, которое гарантирует, что она выполняется как **единое неделимое целое**. Либо транзакция выполняется полностью и успешно, либо не выполняется вообще (откатывается к исходному состоянию).

#### **Основная концепция**

Суть свойства заключается в том, что:
- Транзакция — это набор операций, которые должны быть выполнены все вместе.
- Если хотя бы одна операция завершилась ошибкой, **все изменения откатываются**.
- Не может быть ситуации, когда часть изменений применилась, а часть нет.
- Атомарность защищает данные от повреждения из-за частичных изменений.

> **Важно:** Атомарность — это **"всё или ничего"**. Нет промежуточных состояний.

#### **Преимущества использования**

1. **Целостность данных**
   - Данные никогда не остаются в неконсистентном состоянии.
2. **Надёжность**
   - Система всегда знает, что либо транзакция прошла полностью, либо откатилась.
3. **Упрощение разработки**
   - Программист может группировать операции и не думать о частичных изменениях.
4. **Восстановление после сбоев**
   - При падении сервера незавершённые транзакции откатываются.

#### **Ключевые механизмы реализации**

1. **Журнал транзакций (Transaction Log / Write-Ahead Log)**
   - Перед изменением данных записывается, что именно будет изменено.
   - При сбое журнал используется для восстановления.
2. **Rollback (Откат)**
   - Если транзакция не может завершиться, все изменения отменяются.
3. **Commit (Фиксация)**
   - Если все операции успешны, изменения сохраняются навсегда.
4. **Savepoint**
   - Промежуточная точка сохранения внутри транзакции (можно откатиться до неё).

### Пример: Банковский перевод

Представьте классический пример — перевод денег между двумя банковскими счетами.

**Операции перевода:**
1. Снять 1000₽ со счёта A.
2. Добавить 1000₽ на счёт B.

#### **Без атомарности (нарушение)**

```python
class BankAccount:
    def __init__(self, balance: int):
        self.balance = balance

def transfer_without_atomicity(src: BankAccount, dst: BankAccount, amount: int):
    # Шаг 1: Снимаем деньги
    if src.balance < amount:
        print("Недостаточно средств")
        return False
    
    src.balance -= amount
    print(f"Списано {amount} со счёта A. Остаток: {src.balance}")
    
    # Представим, что здесь произошла ошибка!
    # Например, база данных упала, сеть оборвалась, диск переполнился
    if amount > 500:  # Симуляция ошибки
        raise Exception("Внезапная ошибка!")
    
    # Шаг 2: Зачисляем деньги
    dst.balance += amount
    print(f"Зачислено {amount} на счёт B. Остаток: {dst.balance}")
    
    return True

# Использование
a = BankAccount(2000)
b = BankAccount(0)

try:
    transfer_without_atomicity(a, b, 1000)
except Exception as e:
    print(f"Ошибка: {e}")
    print(f"Счёт A: {a.balance}")  # 1000 (деньги списались!)
    print(f"Счёт B: {b.balance}")  # 0 (деньги не зачислились!)
    # ❌ ДЕНЬГИ ПОТЕРЯНЫ!
```

Проблема: деньги списались со счёта A, но не зачислились на счёт B. Данные повреждены.

#### **С атомарностью (правильное решение)**

```python
class BankAccount:
    def __init__(self, balance: int):
        self.balance = balance
    
    def withdraw(self, amount: int):
        if self.balance < amount:
            raise ValueError("Недостаточно средств")
        self.balance -= amount
    
    def deposit(self, amount: int):
        self.balance += amount

class TransactionManager:
    def __init__(self):
        self.log = []  # Журнал изменений для отката
    
    def begin(self):
        self.log = []
        print("Начало транзакции")
    
    def execute_with_atomicity(self, operations: list):
        """Выполняет список операций атомарно."""
        self.begin()
        try:
            for operation in operations:
                operation()  # Выполняем операцию
                self.log.append(operation)  # Запоминаем успешные операции
            self.commit()
        except Exception as e:
            print(f"Ошибка: {e}. Откат транзакции...")
            self.rollback()
            raise
    
    def commit(self):
        print("✅ Транзакция зафиксирована (COMMIT)")
    
    def rollback(self):
        print("🔄 Откат транзакции (ROLLBACK)")
        # В реальной БД откат происходит через логи
        self.log.clear()

# Атомарный перевод
def atomic_transfer(src: BankAccount, dst: BankAccount, amount: int):
    tm = TransactionManager()
    
    def withdraw():
        src.withdraw(amount)
        print(f"Списано {amount} со счёта A")
    
    def deposit():
        dst.deposit(amount)
        print(f"Зачислено {amount} на счёт B")
    
    try:
        tm.execute_with_atomicity([withdraw, deposit])
        return True
    except Exception:
        return False

# Использование
a = BankAccount(2000)
b = BankAccount(0)

try:
    atomic_transfer(a, b, 1000)
    print(f"Счёт A: {a.balance}")  # 1000
    print(f"Счёт B: {b.balance}")  # 1000
except Exception:
    print(f"Счёт A: {a.balance}")  # 2000 (вернулись!)
    print(f"Счёт B: {b.balance}")  # 0 (денег не было!)
```

Теперь:
- Если операция прервалась, всё откатилось.
- Данные целостны.
- Можно безопасно повторять транзакцию.

### Как работают транзакции в реальных БД

```sql
-- Начало транзакции
BEGIN TRANSACTION;

-- Шаг 1: Снимаем деньги
UPDATE accounts SET balance = balance - 1000 WHERE id = 1;

-- Шаг 2: Зачисляем деньги
UPDATE accounts SET balance = balance + 1000 WHERE id = 2;

-- Если всё ок — фиксируем
COMMIT;

-- Если ошибка — откатываем
ROLLBACK;
```

**В PostgreSQL / MySQL / Oracle**:
- `BEGIN` — начало транзакции.
- `COMMIT` — фиксация (все изменения становятся постоянными).
- `ROLLBACK` — откат (все изменения отменяются).
- Если соединение разорвалось — автоматический `ROLLBACK`.

### Когда использовать атомарность

| Ситуация | Нужна ли атомарность |
|----------|---------------------|
| **Банковские переводы** | ✅ Обязательно |
| **Оформление заказа в магазине** (списание товара + списание денег) | ✅ Обязательно |
| **Регистрация пользователя** (создать профиль + отправить email) | ✅ Да |
| **Чтение данных** (SELECT без изменений) | ❌ Не нужна |
| **Аналитические отчёты** | ❌ Не нужна |
| **Логирование** | ❌ Не нужна |
| **Обновление кэша** | ⚠️ Желательно |

---

### Лучшие практики

1. **Держите транзакции короткими**
   - Чем дольше транзакция, тем выше риск конфликтов и блокировок.
2. **Не смешивайте бизнес-логику и транзакции**
   - Валидацию делайте до начала транзакции.
3. **Используйте явные `BEGIN` и `COMMIT`**
   - Не полагайтесь на авто-коммит (он может скрыть проблемы).
4. **Обрабатывайте исключения корректно**
   - При любой ошибке должен срабатывать `ROLLBACK`.
5. **Транзакции должны быть идемпотентными**
   - Повторный запуск не должен приводить к дублированию (используйте уникальные ключи).
6. **Используйте savepoints для сложных транзакций**
   ```sql
   SAVEPOINT sp1;
   -- выполняем операции
   ROLLBACK TO SAVEPOINT sp1;  -- откат только до точки
   ```

---

### Распространённые ошибки

| Ошибка | Почему плохо | Решение |
|--------|-------------|---------|
| **Авто-коммит включён** | Каждая операция — отдельная транзакция. Нельзя откатить | Отключить авто-коммит |
| **Слишком большие транзакции** | Долгие блокировки, снижение производительности | Разбивать на маленькие |
| **Игнорирование ошибок** | Частичные изменения не откатываются | Обрабатывать ошибки и делать ROLLBACK |
| **Смешанные операции** | В одной транзакции читаем и пишем — повышаем риск дедлоков | Читать вне транзакции |
| **Нет обработки таймаутов** | Транзакция висит вечно, блокируя ресурсы | Устанавливать таймауты |

## Пример из жизни: Покупка в интернет-магазине

Представьте, что вы покупаете товар в интернет-магазине. Процесс:

1. 🛒 Вы нажимаете «Купить».
2. 💳 С вашей карты списываются деньги.
3. 📦 Товар резервируется на складе.
4. ✉️ Вам приходит письмо с подтверждением.

**Без атомарности:**
- Деньги списались, но товар закончился → вы без денег и без товара.
- Товар зарезервировали, но письмо не ушло → вы не знаете о заказе.

**С атомарностью (транзакция):**
- Если не хватило денег → откат, товар не резервируется.
- Если нет товара на складе → откат, деньги не списываются.
- Если письмо не отправилось → всё равно откат (деньги возвращаются, товар освобождается).

### Вывод

**Атомарность** — это фундаментальное свойство ACID, которое защищает данные от частичных изменений. Она гарантирует, что транзакция либо выполняется полностью, либо не выполняется вообще. Без атомарности любые сбои (падение сервера, ошибка сети, дисконнект) приводят к повреждению данных.

Помните главное правило атомарности: **Всё или ничего.**
