# Open/Closed Principle (OCP)

**Open/Closed Principle (Принцип открытости/закрытости)** — программные сущности (классы, модули, функции) должны быть **открыты для расширения**, но **закрыты для модификации**.

#### **Основная концепция**

Суть принципа заключается в том, что:
- Вы можете добавить новую функциональность, не изменяя существующий проверенный код.
- Для этого используется абстракция (наследование, интерфейсы, композиция).
- Базовый код остается нетронутым, что снижает риск появления багов.

#### **Преимущества использования**

1. **Стабильность системы**
   - Существующий код не изменяется → уже работает как надо.
2. **Гибкость и расширяемость**
   - Новые требования реализуются через добавление новых классов.
3. **Безопасность**
   - Не нужно перетестировать весь старый функционал.
4. **Снижение связанности**
   - Зависимость строится от абстракций, а не от конкретных реализаций.

#### **Ключевые компоненты**

1. **Абстрактный базовый класс или интерфейс** — определяет контракт.
2. **Конкретные реализации** — расширяют абстракцию под новые требования.
3. **Клиентский код** — работает с абстракцией, не зная о конкретных реализациях.

---

### Пример: Расчет скидок в интернет-магазине

Предположим, у нас есть класс `DiscountCalculator`, который вычисляет скидку для разных типов клиентов.

#### **Нарушение OCP**

Каждый раз, когда появляется новый тип клиента, приходится изменять метод `calculate` с помощью `if/elif`.

```python
class DiscountCalculator:
    def calculate(self, customer_type: str, amount: float) -> float:
        if customer_type == "regular":
            return amount * 0.95  # 5% скидка
        elif customer_type == "vip":
            return amount * 0.90  # 10% скидка
        # При добавлении "super_vip" нужно МЕНЯТЬ этот метод
        else:
            return amount
```

#### **Соблюдение OCP**

Выносим логику расчета в отдельные классы, реализующие общий интерфейс.

```python
from abc import ABC, abstractmethod

class DiscountStrategy(ABC):
    @abstractmethod
    def calculate(self, amount: float) -> float:
        pass

class RegularDiscount(DiscountStrategy):
    def calculate(self, amount: float) -> float:
        return amount * 0.95

class VipDiscount(DiscountStrategy):
    def calculate(self, amount: float) -> float:
        return amount * 0.90

class SuperVipDiscount(DiscountStrategy):  # Новый тип — просто добавляем класс
    def calculate(self, amount: float) -> float:
        return amount * 0.85

class DiscountCalculator:
    def calculate(self, strategy: DiscountStrategy, amount: float) -> float:
        return strategy.calculate(amount)

# Использование
calculator = DiscountCalculator()
print(calculator.calculate(RegularDiscount(), 1000))   # 950
print(calculator.calculate(VipDiscount(), 1000))       # 900
print(calculator.calculate(SuperVipDiscount(), 1000))  # 850
```

Теперь для добавления `SuperVipDiscount` мы **расширили** систему новым классом, **не меняя** `DiscountCalculator`.

---

### Когда использовать

1. **Часто меняющиеся требования**
   - Если бизнес-логика регулярно обрастает новыми вариантами поведения.
2. **Стабильное ядро системы**
   - Базовые модули должны быть защищены от изменений.
3. **Код, который уже протестирован и работает**
   - Не хочется рисковать, переписывая его под каждый новый случай.

---

### Лучшие практики

1. **Стратегия (Strategy Pattern) как реализация OCP**
   - Паттерн Стратегия — классический способ соблюсти OCP.
2. **Выделяйте то, что часто меняется**
   - Изменчивые части выносите за абстракции.
3. **Не усложняйте заранее**
   - Если новых вариаций не ожидается, простой `if` тоже ок.

---

### Альтернативы и дополнения

1. **Factory Method / Abstract Factory**
   - Помогают создавать объекты расширяющих классов без изменения клиентского кода.
2. **Dependency Injection**
   - Подает нужную реализацию стратегии извне.

## Пример из жизни: Розетка

Электрическая розетка (базовый интерфейс) **закрыта для модификации** — вы не переделываете её, чтобы подключить новый прибор. Но она **открыта для расширения** — вы можете воткнуть в неё утюг, чайник, зарядку для телефона. Каждый прибор — новая реализация интерфейса «вилка».

---

### Вывод

**OCP** — это про защиту стабильного кода от изменений. Вместо того чтобы править старые классы, вы добавляете новые. Система становится гибкой, надежной и готовой к новым требованиям без риска сломать то, что уже работает.
