# Single Responsibility Principle (SRP)

**Single Responsibility Principle (Принцип единственной ответственности)** — каждый класс должен иметь только одну причину для изменения. Другими словами, класс должен решать только одну задачу.

#### **Основная концепция**

Суть принципа заключается в том, что:
- Класс должен быть полностью сфокусирован на одной сущности или действии.
- Если класс берет на себя несколько обязанностей, изменение в одной из них может сломать другие.

#### **Преимущества использования**

1. **Упрощение отладки**
   - Если класс делает только одно, ошибки легче локализовать.
2. **Повышение переиспользуемости**
   - Узкоспециализированные классы проще использовать в других проектах.
3. **Улучшение читаемости**
   - Код становится понятнее за счет четкого разделения логики.
4. **Облегчение тестирования**
   - Тестировать маленькую ответственность проще, чем монстра.

#### **Ключевые компоненты**

1. **Класс с единственной зоной ответственности** — не делает ничего лишнего.
2. **Разделение логики** — если появляется вторая ответственность, создается новый класс.

### Пример: Отчет о сотрудниках

Представьте класс, который считает зарплату **и** сохраняет отчет в файл. Это две разные причины для изменения: налоги могут поменяться, или формат файла.

#### **Нарушение SRP**

```python
class Employee:
    def __init__(self, name, hours_worked, hourly_rate):
        self.name = name
        self.hours_worked = hours_worked
        self.hourly_rate = hourly_rate

    def calculate_salary(self):
        return self.hours_worked * self.hourly_rate

    def save_to_file(self, filename):
        with open(filename, 'w') as f:
            f.write(f"{self.name}: {self.calculate_salary()}")
```

#### **Соблюдение SRP**

```python
class Employee:
    def __init__(self, name, hours_worked, hourly_rate):
        self.name = name
        self.hours_worked = hours_worked
        self.hourly_rate = hourly_rate

    def calculate_salary(self):
        return self.hours_worked * self.hourly_rate

class EmployeeReportSaver:
    @staticmethod
    def save_to_file(employee: Employee, filename: str):
        with open(filename, 'w') as f:
            f.write(f"{employee.name}: {employee.calculate_salary()}")
```

---

### Когда использовать

- Когда видите, что класс меняется по разным причинам.
- Когда класс трудно тестировать из-за большого количества зависимостей.
- Когда нужно переиспользовать часть логики.

---

### Лучшие практики

1. **Спрашивайте себя**: "Почему я могу изменить этот класс?" — если ответов >1, нарушаете SRP.
2. **Не фанатизм**: иногда допустимо объединять две связанные обязанности, если они почти не меняются.

---

## Пример из жизни: Повар в ресторане

Повар готовит еду. Если он же будет мыть посуду и встречать гостей — это SRP нарушен. При изменении графика мытья посуды повар начнет ошибаться в рецептах. Лучше: повар готовит, посудомойка моет, администратор встречает.

---

### Вывод

**SRP** — это фундамент чистого кода. Заставляя класс делать одно дело, вы снижаете связанность и повышаете устойчивость системы к изменениям.
