# Принцип 4: Interface Segregation Principle (ISP)

**Interface Segregation Principle (Принцип разделения интерфейсов)** — клиенты не должны зависеть от методов, которые они не используют. Лучше иметь несколько специализированных интерфейсов, чем один «толстый» интерфейс.

#### **Основная концепция**

Суть принципа заключается в том, что:
- Нельзя заставлять класс реализовывать методы, которые ему не нужны.
- Большие интерфейсы следует разбивать на более мелкие и узкоспециализированные.
- Класс реализует только те интерфейсы, которые действительно ему нужны.

#### **Преимущества использования**

1. **Уменьшение связанности**
   - Клиенты не знают о методах, которые не используют.
2. **Упрощение понимания кода**
   - Маленькие интерфейсы понятнее и легче в реализации.
3. **Повышение переиспользуемости**
   - Узкие интерфейсы можно комбинировать в разных классах.
4. **Облегчение тестирования**
   - Моки становятся проще — не нужно реализовывать 20 ненужных методов.

#### **Ключевые компоненты**

1. **«Толстый» интерфейс (anti-pattern)** — один интерфейс, который пытается делать всё сразу.
2. **Разделенные интерфейсы** — несколько маленьких интерфейсов по разным зонам ответственности.
3. **Клиенты** — каждый клиент использует только нужные ему интерфейсы.

---

### Пример: Многофункциональный принтер

Представьте интерфейс `МФУ`, который включает в себя печать, сканирование и отправку факса.

#### **Нарушение ISP**

```python
from abc import ABC, abstractmethod

class MultiFunctionDevice(ABC):
    @abstractmethod
    def print_document(self, content: str):
        pass

    @abstractmethod
    def scan_document(self) -> str:
        pass

    @abstractmethod
    def send_fax(self, number: str, content: str):
        pass

# Старый принтер, который умеет только печатать
class OldPrinter(MultiFunctionDevice):
    def print_document(self, content: str):
        print(f"Печать: {content}")

    def scan_document(self) -> str:
        # Старый принтер не умеет сканировать!
        raise NotImplementedError("Сканирование не поддерживается")

    def send_fax(self, number: str, content: str):
        # Старый принтер не умеет отправлять факсы!
        raise NotImplementedError("Отправка факсов не поддерживается")

# Использование
printer = OldPrinter()
printer.print_document("Hello")
# А если кто-то вызовет scan_document() — упадёт с ошибкой
```

Проблема: `OldPrinter` вынужден реализовывать методы, которые ему не нужны, либо бросать исключения. Клиент, который ожидает `MultiFunctionDevice`, может вызвать `scan_document()` и всё сломается.

#### **Соблюдение ISP**

Разделяем толстый интерфейс на несколько маленьких.

```python
from abc import ABC, abstractmethod

# Узкие интерфейсы
class Printer(ABC):
    @abstractmethod
    def print_document(self, content: str):
        pass

class Scanner(ABC):
    @abstractmethod
    def scan_document(self) -> str:
        pass

class FaxSender(ABC):
    @abstractmethod
    def send_fax(self, number: str, content: str):
        pass

# Теперь каждый класс реализует только то, что умеет
class OldPrinter(Printer):
    def print_document(self, content: str):
        print(f"Печать: {content}")

class AdvancedPrinter(Printer, Scanner):
    def print_document(self, content: str):
        print(f"Печать: {content}")

    def scan_document(self) -> str:
        return f"Сканированное содержимое"

class FullMFP(Printer, Scanner, FaxSender):
    def print_document(self, content: str):
        print(f"Печать: {content}")

    def scan_document(self) -> str:
        return f"Сканированное содержимое"

    def send_fax(self, number: str, content: str):
        print(f"Отправка факса на номер {number}: {content}")

# Клиенты зависят только от нужных интерфейсов
def use_printer(device: Printer):
    device.print_document("Документ")

def use_scanner(device: Scanner):
    content = device.scan_document()
    print(f"Получено: {content}")

# Старый принтер можно использовать только как принтер
printer = OldPrinter()
use_printer(printer)        # ✅ Работает
# use_scanner(printer)      # ❌ Ошибка типов — не пройдёт проверку!
```

---

### Когда использовать

1. **Толстые интерфейсы начинают появляться**
   - Если интерфейс имеет 5+ методов и некоторые из них не нужны части клиентов.
2. **Часто бросаются `NotImplementedError`**
   - Это явный признак нарушения ISP.
3. **Нужна гибкая компоновка функциональности**
   - Разные объекты могут реализовывать разные комбинации маленьких интерфейсов.

---

### Лучшие практики

1. **ISP работает в связке с SRP**
   - Если интерфейс соответствует единственной ответственности, он уже узкий.
2. **Интерфейсы должны быть клиенто-ориентированными**
   - Проектируйте интерфейс под нужды конкретного клиента, а не под возможности сервера.
3. **Не бойтесь множественного наследования интерфейсов**
   - В Python это естественно и безопасно (в отличие от множественного наследования классов).

---

### Альтернативы и дополнения

1. **Адаптер (Adapter Pattern)**
   - Если вы не можете изменить существующий толстый интерфейс, можно создать адаптер, который предоставляет только нужные методы.
2. **Декоратор (Decorator Pattern)**
   - Позволяет добавлять функциональность по кусочкам, что созвучно идее ISP.

## Пример из жизни: Ресторанное меню

Представьте, что в ресторане есть одно гигантское меню на 100 страниц: завтраки, обеды, десерты, барная карта, детское меню и т.д. Если вы пришли просто пообедать, вы вынуждены листать всё меню целиком — неудобно.

Лучше: отдельные меню — «Бизнес-ланчи», «Барная карта», «Десерты». Каждый клиент получает только то меню, которое ему нужно. Это и есть ISP в реальной жизни.

---

### Вывод

**ISP** — про то, чтобы не навязывать лишнего. Клиент должен знать только о методах, которые он реально вызывает. Чем уже интерфейс, тем легче его реализовать, тестировать и использовать. Если вы ловите себя на том, что пишете `pass`, `return None` или `raise NotImplementedError` — это звонок, что пора разделять интерфейс.
